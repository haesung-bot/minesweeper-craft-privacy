# 03. 마이크 감시, 내 손으로 직접 터뜨려서 확인하기

목표: "실시간 마이크 감시"가 **진짜로 작동하는지** 가짜 상황이 아니라 실제 신호로 확인한다.

이 저장소에는 이제 **두 개의 앱**이 있다.

| 앱 | 모듈 | 역할 |
|---|---|---|
| 🛡️ PhoneGuard | `app/` | 감시하는 쪽. 다른 앱의 마이크 사용을 실시간으로 지켜본다 |
| 🎯 MicTest Target | `mictest/` | 터지는 쪽(표적). 버튼 하나로 마이크를 진짜로 켠다 |

> ⚠️ **MicTest Target은 백신 테스트의 EICAR 파일과 같은 역할이다.**
> 마이크를 **진짜로** 열어서 안드로이드가 "사용 중"으로 인식하게 만들지만,
> 읽은 소리는 화면에 보여주지도, 저장하지도, 분석하지도, 전송하지도 않는다.
> 읽는 즉시 버린다. **INTERNET 권한 자체가 없어서** 설령 코드에 실수가 있어도
> 밖으로 보낼 방법이 없다. 본인 소유 기기에서만 쓴다.

---

## 빌드하기

지난 가이드([01-build-on-my-pc.md](01-build-on-my-pc.md))대로 Android Studio에서
`phone-guard` 폴더를 열면 `app`, `mictest` **두 모듈이 자동으로 다 보인다**.

둘 다 설치:
```bash
./gradlew installDebug
```
(Windows: `.\gradlew.bat installDebug`)

둘 다 폰에 설치된다. 앱 아이콘이 두 개 생긴다 — "PhoneGuard"와 "MicTest Target".

---

## 실제로 터뜨려보기 (닫힌 루프 테스트)

1. **PhoneGuard**를 열고 `실시간 마이크 감시 시작`을 누른다
   → "✅ 테스트 표적(MicTest Target) 설치 확인됨" 이 보이면 두 앱이 서로 인식한 것
2. 홈 화면으로 나가서 **MicTest Target**을 연다
3. `마이크 테스트 시작` 버튼 → 권한 팝업이 뜬다 → **허용**
4. 화면에 `🔴 마이크 테스트 중...` 이 뜨면 지금 진짜로 마이크가 열린 상태다
5. 다시 **PhoneGuard**로 돌아온다(최근 앱 전환)
6. 화면에 이렇게 떠야 한다:

   ```
   ✅ [자가 테스트 표적 감지됨] MicTest Target (com.phoneguard.mictest) 마이크 사용 🔴 시작
   ```

7. MicTest Target으로 다시 가서 `마이크 테스트 중지` → PhoneGuard로 돌아오면
   `⚪ 종료` 가 떠야 한다

| 결과 | 의미 |
|---|---|
| 정확히 떴다 | 감시 기능이 **진짜로** 작동한다는 걸 직접 확인했다 ✅ |
| 패키지명이 가려지고 "뭔가 켜졌다"만 뜬다 | 제조사가 다른 앱 식별을 막아둔 것 — 그 자체로 괜찮은 보안 설계 |
| "지원 안 됨" 메시지 | Android 11 미만이거나 이 기기가 API를 막아둔 경우 |

## 보너스: 두 가지 렌즈가 다르게 본다는 것 직접 확인하기

PhoneGuard에서 `마이크 권한 점검`(실시간 감시가 아니라 **권한 점검**)을 눌러본다.
MicTest Target은 목록에 뜨지만 **LOW(10점)** 로 나와야 한다.

왜일까? MicTest Target은 **INTERNET 권한이 없어서** "마이크+인터넷=유출 위험" 조합이
안 걸린다. 지금 실제로 마이크를 켜고 있어도(실시간 감시로는 잡히는 것과 똑같이),
"권한 조합"만 보는 점검으로는 위험해 보이지 않는다.

> 📌 이게 바로 **"권한을 가졌다"와 "지금 쓰고 있다"가 다른 질문**이라는 걸 보여주는
> 좋은 예다. 실제 보안 도구들도 이 두 가지를 다른 방법으로 따로 본다 — 하나는
> 설치 시점 정적 분석(권한 점검), 하나는 런타임 동적 감시(실시간 감시).
